# Complete table and browser acceptance

Use this route when R assembles a manuscript table from completed Mplus OUT/GH5
files. Keep successful cell readback, a complete table, actual browser rendering
and scientific adoption as separate results.

## Bind the exact displayed cells

Derive required producers from the frozen table's path rows, member roles and
sample columns. A broad discovery index can conservatively list more producers
than a particular table displays. Accept the smaller dependency set only after
every expected cell has a unique, source-bound producer; do not reduce the
authorized model universe. A few hundred verified cells spread over incomplete
tables do not count as complete table deliveries.

Record the actual point/interval source, draw slice, quantile rule and symbol
decision for each cell. Historical reproduction may preserve different slices
in different code branches; this does not endorse that choice for new inference.
Independently recompute values and symbols from the raw GH5/OUT, then bind the
cell CSV, readback receipt, readiness table, checker version and exact producer
hashes. A saved PASS without these bindings becomes stale when its CSV changes.

Require the full expected cell set before rendering. Parse the resulting HTML
and compare every displayed cell, row label, sample column and spouse header to
the validated data. Route by the declared table family: the presence of a
file such as `CELL_BINDINGS.csv` cannot distinguish table families that both
export that file. Check malformed source sets and changed symbols even when
an altered candidate has a fresh, internally consistent file hash.

## Reuse verified extraction before rendering

When a calibrated snapshot already contains the required cells, bind and copy
its RDS, cell data, readiness and independent numeric receipts before rendering
the selected complete tables. Verify every copied hash and the original
producer bindings. A rendering retry need not repeat extraction or Mplus fits.
In one Windows replay this route produced two tables with 66 and 72 cells,
then passed the same HTML, actual-browser, visual and terminal checks below.

Record the execution mode that actually occurred. A short synchronous RStudio
render has a real response and completion receipt but no background job to
invent or worker to close. Preserve the main session. If connection acceptance
uses an independently tested MCP stdio route, label that evidence separately
from the native synchronous producer response. Reusing data does not close
upstream provenance or scientific-adoption decisions.

## Inspect the real browser output

Save a screenshot from the actual HTML in an owned browser profile. Verify the
column spans, row widths, expected row count, symbol counts and scope note.
Inspect the screenshot itself for clipping, readable labels and missing glyphs
before recording visual acceptance. A successful browser smoke on a direct
effect table does not test the conditional-table branch.

After screenshot success, persist a pending-exit receipt with HTML/image hashes
and each owned browser PID **and creation time**, before requesting closure.
If shutdown is slow, preserve these artifacts and continue estimation or other
independent work. Resume the exit check instead of creating another browser or
recomputing the table. Any permitted cleanup must be confined to the verified
owned identities; a parent PID alone cannot identify a current child after PID
reuse. Record failed cleanup and actual actions without claiming memory freed.

On Windows, a PID can remain queryable after its process exits. A reported exit
code of zero can also precede completion of process teardown. Open a native
process handle with query and synchronization rights, compare creation time,
and use `WaitForSingleObject(handle, 0)` on that **same handle**: a signaled
process establishes termination; a timeout does not. Declare 64-bit ctypes
handle signatures and always close the handle. Access denied is unknown, not
proof of exit. Use a narrowly measured timestamp tolerance for serialization
precision, not a broad PID-reuse grace period.

Persist the successful terminal observation and its checker/artifact hashes.
That exact process identity cannot later reactivate. A later lookup of the
same PID may refer to a new protected process and fail; validate the previously
bound terminal observation instead of invalidating it or touching the new
process. Check that every original identity is covered and each observation
proves exit, absence or reuse. Do not turn an earlier timeout or access denial
into terminal evidence.

## Add one manuscript object once

Require numeric bindings, actual HTML verification, image hashes, genuine
visual review and owned-browser terminal evidence before marking the table
complete. Keep the scope note with the deliverable when upstream provenance or
scientific adoption remains open. Count unique manuscript identities across
the entire accepted history; neither duplicate formats nor another worker's
completed registry entry increases the table count.

A Windows conditional-table execution exercised this full route on 48 cells
from 24 completed producers. All displayed symbols matched the frozen rule;
an independent readback also checked 1,420 numeric values across the available
cell snapshot. The larger readback count did not become a claim that every
table was complete. Browser shutdown recovery reused the existing screenshot,
and no successful forced termination or new Mplus fit was required.
