# 真实长任务：已测范围与效率

2026-11-01 在同一 Windows Mplus 9 上，以原字节 INP/DAT 复跑 PP-LGCM
son×urban 的 20 个 A 成员。Mac 独立取回 191 文件、15,146,419 字节，
逐文件传输 SHA 通过；只读核验器复核 20/20 成员的输入、来源元数据、正常终止、
参数和 TECH3 协方差。数值最大差为 0；model.out 除时钟行外一致。
这一次是直接批量 Mplus；R/MplusAutomation 通道另由此前合成配对测试验证。

## 实测时间

| 项目 | 实测 |
|---|---:|
| 同一批次的原 20 份引擎回执 | 2128.7994 秒，约 35.48 分钟 |
| 本次 20 份最终采用输出的引擎时间 | 1559.71 秒，约 26.00 分钟 |
| 首个 worker 开始至最终 worker 结束 | 1626.097 秒，约 27.10 分钟 |
| 完整返回目录打包、传输及本机核 SHA | 8.85 秒 |
| 实际引擎启动次数 | 21；MI19 额外执行一次 |

最后采用的 20 次全部在原每模型 240 秒内完成。探针配置的 cap 为 480 秒，
这是原合同之外的工程差异，不能声称控制设置完全相同。首版准入也未检查
原 commit 门槛；重启后的版本补齐，原失败与版本证据保留。

这次引擎总时间更短，不能据此认定“远程使算法变快”：Windows 的 WSL/RStudio
资源状态、系统负载和观测时间不同，没有随机或交叉控制。批量提交、复用原输入、
只取回所需输出的成本很小，支持 Mac 开发、Windows 计算的分工。此前约 45–53 秒
的完整 Rscript 往返附加成本仍适用于那条具体通道；不要混成单一网络延迟。

## 三种中断分别核验

- Mac 等待进程被终止且确认不再存活；Windows 原 worker 继续运行。
- Mac 服务约停止 6 分 18 秒。期间 Windows 保持同一 worker 的心跳并完成成员；
  服务重启后实测 81.8 秒内重新连通，离线期间已提交的查询按原 ID 取回，
  没有为查询重派模型。这是服务中断测试，不等于休眠、重启或任意断网均可靠。
- Windows worker 被终止后，原引擎仍活着；新 worker 在同一工作目录核验并复用
  18 个已完成成员。MI19 在切换期间自行完成，但缺少 RESULT，旧恢复代码把它
  归档后又运行一次；因此这次不是严格恰好执行一次。新包装器名为 run2，
  模型工作目录未换，不能将两种身份混为“原任务名不变”。

成熟恢复应先验证无 RESULT 的完整孤儿输出，采用后补一份独立完成回执，
仅在确实缺少有效输出且预算允许时重估。实现与负例见
[输出与恢复验收](remote-output-acceptance.md)。不得靠自动重跑来掩盖恢复缺陷。

## 下一次的工作方式

保持 Windows 本地 worker、阶段心跳、原子结果和源哈希；Mac 不持有计算进程。
短时等待到期先取原结果，服务恢复先核身份，worker 恢复先核孤儿引擎和输出。
任务前确认 WSL 自动同步不会把已关闭的 WSL 重新拉起；仅在用户已授权的资源
回收范围内临时暂停，完成后恢复原入口。不要替换原 Codex/Claude 会话。

在 xdev run/detach 将本地 PowerShell 正文嵌入包装脚本时，正文文件用无 BOM
UTF-8。独立推送并直接执行的 Windows PS5.1 文件才按其解释器需要写 UTF-8 BOM。
本次内部 BOM 曾被当成首条命令的一部分，失败在运行查询前，去掉正文 BOM 后通过。

科研状态不因这次复跑增加覆盖：完整 H4 与四个延期收入家族仍未完成。
整夜执行、Windows 休眠/重启以及长期跨网稳定性仍需单独证据。
