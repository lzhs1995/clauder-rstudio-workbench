# Stata 原始数据链的确定性检查

用于原始 DTA → 清洗中间件 → CSV → DAT 的复现诊断。一次同配置复跑相同，仍可能在改变排序种子后出现成员方向和最终行集合变化；已完成对照见本机证据 `stata_raw_chain_sortseed_comparison`。这种结果支持排序随机性影响数据选择，不认证未知的历史种子或历史数据版本。

原始链正常结束与归档数值一致分别验收。即使行数相同，成员方向、保留记录、缺失状态或派生值仍可能不同。先固定来源和执行条件，再检查排序同键记录是否影响结果。与 [数据及表格差异追溯](data-and-table-reconciliation.md) 配合使用。

## 固定比较对象

保存原始文件、作者 DO、实际运行副本、ado 和执行程序的 SHA256；记录 Stata 实际版本和 MP/SE 版本类型、处理器设置、`version` 兼容声明、操作系统、进程/阶段边界及临时目录。源文件只读，日志与中间件进入每次独立目录，不覆盖历史结果。运行前后核对原始输入 SHA。

`version` 的依据必须来自可定位的原脚本或日志；缺少证据时注明假设。它不等于使用旧版可执行程序，也不认证跨平台一致性。若工程副本已经重排完整数据块来解决先读后写依赖，应同时保存原顺序、实际顺序、块对应关系和修改差异；此后“只改路径和版本”必须说明相对于哪个已冻结副本，不能隐去此前重排。

将排序、成员方向选择、供体分组补值、缩尾和完整案例筛选列成依赖链。重点定位：

- `sort`、`gsort`、`bysort` 的键是否存在并列；还要检查 ado 内部排序。
- `by ...: ... _n == 1`、`_N`、`x[_n-1]`、`x[_n+1]`、`duplicates drop ..., force` 是否依赖同键先后。
- actor/partner 是否由某次保留的第一条记录决定；下游是否在映射到成员角色之前分别计算阈值或补值。

`duplicates drop` 保留各重复组的首次出现；只按部分变量判重时，其余字段可能不同。命令存在、键有重复或方向翻转都只是线索，需要比较该语句前后的实际记录选择。[Stata duplicates 手册](https://www.stata.com/manuals/dduplicates.pdf)

定位执行语句时先解析续行与嵌套块注释，再从最终端点逆查实际读入的分支。`gen nvals = _n == 1` 可能仅用于计数；必须跟踪该变量是否参与 `keep`、`drop` 或成员字段赋值，不能看到 `_n == 1` 就认定它选了 actor。记录原稿、运行副本及插入控制行后的行号对应关系。

一种已经核验的风险结构是：两条相反方向记录共享无向 `couple_numb`，`sort couple_numb` 没有第二排序键，随后 `duplicates drop couple_numb, force` 留下一条。保留下来的 `couple1`/`couple2` 决定 actor/partner，后续 `pid_merge` 延续该 actor 身份。需进一步核对保留前的候选集合相同、保留后的方向不同，才能把分叉限定在该选择边界。其他未进入最终 panel 的分支仍可能提前消耗排序随机状态，不能擅自删除。

## 有界、串行的重复实验

先声明运行上限、资源条件、停止规则、比较容差和输出清单。每次使用相同的输入字节、执行程序、ado、阶段顺序及进程划分；保持所有模型和补值规则不变。任何未固定的随机生成、抽样、时间依赖或动态来源都要单列，不能与排序种子变化混为一个原因。

| 运行角色 | 排序控制 | 比较目的 |
| --- | --- | --- |
| 基准 | 保持冻结脚本原设定 | 保存真实执行入口与各端点 |
| 同配置复跑 | 不新增排序种子 | 在相同条件下能否重复得到相同行集合和值 |
| 种子对照 | 仅在预先约定入口加入 `set sortseed`，例如依次使用 1、2、3 | 结果是否对排序种子敏感 |

若完整基准已经存在，上表的示例设计包含已有基准共五次；具体上限以任务授权为准，不为某个目标 N 继续搜索种子。每次保留独立 attempt、开始/结束记录、日志、退出码和产物 SHA。失败或未知终态不当作数值差异；先只读核验引擎日志、退出状态与控制器错误，再按已有授权决定是否新建 attempt。重试保留原失败记录，额外启动计入尝试总数。

种子设置位置是实验条件的一部分。单进程完整链与每阶段新进程的链不同；后者必须记录在哪些进程入口设置种子，保持各次一致。不要在每个 `sort` 前反复重置，也不要改变生产阶段边界来配合种子。诊断代码若额外排序，可能推进排序随机状态；优先对阶段快照在另一进程中检查，避免观察步骤改变生产过程。

## 排序命令的用法与局限

`set sortseed` 设置用于打破排序同键次序的随机种子，影响 `sort`、`gsort` 及内部执行排序的命令。官方帮助将其定位为复现比较工具，并提醒它可能掩盖不完整排序键造成的数据处理问题。它不能赋予“第一条”科学含义，也不能恢复未知的历史种子。[Stata sortseed 帮助](https://www.stata.com/help.cgi?sortseed)

```stata
* 仅加入获准种子对照副本的约定入口，编号为实验控制值
set sortseed 1
query sortseed
```

记录种子时也记录实际命令序列和进程边界；相同数字不自动保证不同代码、输入顺序、版本或平台上的结果一致。仅有模拟/抽样的 `set seed` 日志，不能代替本次 `set sortseed` 控制项及设置位置的证据。

需要局部状态证据时，可按 `help set_sortrngstate` 保存 `c(sortrngstate)`；恢复状态是额外干预，必须单独记录，不能悄悄加入只允许 `set sortseed` 的实验。

```stata
* 仅记录当前排序随机状态；这里不恢复、不重置
local sort_state_before = c(sortrngstate)
display "`sort_state_before'"
```

`sort group_key, stable` 保留同键记录进入这次排序前的相对顺序。如果此前顺序已经不同，它会保留这种差异；它不定义统一的成员方向或供体优先级，也不控制以后其他命令的排序。若研究规则要求组内按另一个字段排序，应明确写出完整键，并核验最后仍有无并列；不能把临时行号当作历史身份规则。[Stata sort 手册](https://www.stata.com/manuals/dsort.pdf)

```stata
* 语法示例：仅适用于另获授权的排序规则版本，不加入种子对照
sort group_key, stable

* 若已经有明确且经过核验的优先级规则，可显式写完整排序键
sort group_key documented_priority stable_record_key
```

这两段示例表示不同规则，不应连续复制到历史重放脚本。加入 `stable`、补完整键、固定妻/夫方向或改变父母供体键，都可能改变保留记录或研究语义；应另存版本并取得相应范围授权。纯种子诊断不混入这些改动。

Stata 17 更换了默认排序方法。`sort` 遵循用户版本控制：do-file 的兼容版本、交互设置和 ado/program 内的版本声明不能一概等同。记录实际 `set sortmethod` 与调用环境，不要仅凭操作系统或版本号不同就认定差异原因，也不要在种子对照中同时切换排序方法。[排序方法](https://www.stata.com/manuals/psetsortmethod.pdf)

官方文档还明确指出，Stata/SE 与 Stata/MP、不同 MP 处理器数以及 `qsort`/`fsort` 可以在同一随机种子或状态下产生不同的同键次序。因此这些都是需要固定的实验条件；跨版本、跨机器复现须另验，不能由同机种子对照代替。[排序随机状态](https://www.stata.com/manuals/psetsortrngstate.pdf)

## 比较、定位与判读

按各端点的真实 schema 核对列集合、列序、N、身份键、重复键、行集合、行序、缺失状态和逐列值。对长字符串 ID 保留字符精度；历史数值 DAT 若已舍入身份，单列候选连接与精确身份的证据边界。字节 SHA 不同可能包含保存元数据或顺序变化，需要进一步比值；同 N 或同 SHA 摘要之外的成功标记不代替这些检查。

夫妻链同时保留原有有向键和经过关系认证的无向“双方 ID + 波次”键。有向比较回答原表是否相同；无向比较帮助识别同一对成员的方向变化。角色重排只用于诊断，不能取代正式比较或用性别、同户关系制造配偶。仅比较了部分角色字段时，结论只覆盖这些列。

完整案例门应在每份保存的筛选前数据上逐行重放，核对缺失字段计数及保留集合，再列共同、各自独有和净差。净少若干行不等于只删除那几行。若进一步重放补值或阈值处理，应写明输入条件：从保存字段和观察到的 actor 选择重现下游，不等于已经解释上游为什么选择这个 actor，更不证明供体关系科学合理。

| 观察结果 | 可报告结论 | 仍需保留的边界 |
| --- | --- | --- |
| 同配置复跑的行集合或值不同 | 本次条件下未能重复得到相同结果 | 还需排除其他未控制因素，不能只据此锁定某条排序语句 |
| 同配置复跑相同，但改变排序种子后方向或行集合不同 | 同配置重复通过，排序种子敏感性已检出 | 默认状态下重复相同不证明排序规则完整，也不能推出历史种子 |
| 仅改变排序种子，输入及其他条件一致，结果不同 | 本链对所测排序种子敏感 | 定位具体语句需要最早出现选择变化的阶段/语句前后证据；后续放大机制另核 |
| 所测运行结果全部相同 | 本次有限对照未检出排序种子敏感性 | 不排除未测试状态、其他排序路径或数据/版本差异；历史来源保持 OPEN |
| 某个种子得到历史 N | 样本量相符，属于候选线索 | 未认证历史种子、身份集合、数值或生产顺序 |
| 在保存输入下补值/筛选精确重放 | 指定下游机制得到验证 | 不升级为全原始链数值一致、历史首次分叉定位或研究语义正确 |

具体排序根因需要同时绑定：语句和 ado SHA、位置、排序键的并列情况、操作前输入顺序、被选记录/成员方向的变化，以及该变化如何进入下游。若现有阶段日志不足，只报告能够定位的最早阶段；额外语句插桩必须保持独立诊断副本并记录新增操作，不能把最终端点差异冒充历史首个分叉。

若排序种子改变了 actor，而原有补值、阈值或完整案例门依赖 actor，最终 CSV 的成员集合也会改变。此时应分别报告“排序随机性影响成员方向”“下游规则如何传递该变化”和“归档版本不能凭现有条件唯一恢复”。即使某次恰好得到归档行数，也不升级为历史身份与数值复现 PASS。

## 交付与公开边界

分开记录工程执行、归档数值一致、确定性实验、历史来源、研究语义和模型估计的状态。一次 `rc=0` 只证明相应工程步骤完成；出现差异时保存产物、解释条件和未决项，不据此替换论文数据或自动重估模型。

每次私有证据至少绑定输入/代码/运行时 SHA、实际控制项、日志、端点 schema、身份对齐方式、缺失比较和状态。公共 skill 只保留变量名、行列数、比对项数、PASS/FAIL、最大绝对差、SHA 和方法；真实 ID/个体值、估计值、本机绝对路径及样本量以外描述统计留在私有证据目录，用逻辑证据名引用。

命令语义已按上述 Stata 官方在线帮助/手册及安装内帮助核对。具体任务的数值结果与历史来源结论，仍以该任务保存的真实运行回执和逐项比较证据为准。
